# Сценарий: недоставленное SMS

**Идентификатор для JSON поля `scenario`:** `sms_delivery`

**Слоты (`slots`):** для шага с запросом к БД обязателен ключ `phone` (строка — абонентский номер, как вы определили из текста; не цифры из почты или версии приложения).

**Инструменты MCP:** сценарий использует отдельные MCP-сервисы. Планировщик может выбирать только эти tools:
- `auth.get_user_activity_by_phone(phone)` — возвращает пользователя и `is_active`;
- `auth.get_user_by_phone(phone)` — возвращает найденных пользователей auth;
- `sms.get_recent_sms_by_phone(phone, limit)` — возвращает историю отправленных SMS.

Не пиши SQL. Для получения фактов выбирай MCP tools из списка выше.

Когда пользователь спрашивает, почему клиенту не пришло SMS, без дополнительных деталей, действуй по шагам:

1. Определи абонентский номер из сообщения пользователя.
   - Если номер не удаётся определить надёжно — `next`: `finish`, `scenario`: `sms_delivery`, `slots`: `{}`, в `task`/`reason` попроси номер в формате `8XXXXXXXXXX`.

2. Если номер есть и нужны факты — `next`: `db`, `scenario`: `sms_delivery`, `slots`: `{"phone":"<определённый номер>"}`.
   - Сформируй `task`: что нужно выяснить: активность пользователя в auth и последние отправленные SMS.

3. Если записей SMS нет — в финальном ответе явно скажи об этом (после статуса auth, если применимо).

4. Если записи SMS есть — краткий вывод по причине недоставки и перечисление найденных записей.
