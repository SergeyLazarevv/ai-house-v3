# Сценарий: недоставленное SMS

**Идентификатор для JSON поля `scenario`:** `sms_delivery`

**Слоты (`slots`):** для шага с запросом к БД обязателен ключ `phone` (строка — абонентский номер, как вы определили из текста; не цифры из почты или версии приложения).

**Подстановка в SQL:** в запросах оставляй плейсхолдеры `{{phone10}}` (10 цифр после ведущей 7/8), `{{phone11}}` (11 цифр с ведущей 7 для auth_data), `{{user_message_phone}}` (формат 8XXXXXXXXXX) — исполнитель подставит их из нормализованного `slots.phone`.

**Доступные алиасы БД (target):** `auth` — БД с `public.users`; `main` и при наличии `billing` — БД сервиса SMS (`send_sms` и связанные таблицы). Сначала при наличии DSN auth выполни простую проверку активности (`is_active`); если `is_active=false`, не запрашивай SMS.

Когда пользователь спрашивает, почему клиенту не пришло SMS, без дополнительных деталей, действуй по шагам:

1. Определи абонентский номер из сообщения пользователя.
   - Если номер не удаётся определить надёжно — `next`: `finish`, `scenario`: `sms_delivery`, `slots`: `{}`, в `task`/`reason` попроси номер в формате `8XXXXXXXXXX`.

2. Если номер есть и нужны факты из БД — `next`: `db`, `scenario`: `sms_delivery`, `slots`: `{"phone":"<определённый номер>"}`.
   - Сформируй `task`: что нужно выяснить (auth + последние SMS). Исполнитель сам сгенерирует SQL по этому сценарию; ты можешь вставить примеры SQL в ```sql``` как подсказку.

3. Пример SQL для **auth** (один простой SELECT, результат должен вернуть поле активности пользователя):

```sql
SELECT
  u.phone,
  u.is_active
FROM public.users u
WHERE u.phone::text = '{{phone11}}'
LIMIT 1
```

4. Пример SQL для **SMS** (алиас `main` или `billing` — как настроено в окружении):

```sql
SELECT
  ss.phone_number,
  ss.received_date,
  ss.sending_date,
  ss.sms_text,
  ss.result,
  ss.error_text,
  oa.sender_name,
  op.type AS operator_type,
  op.name AS operator_name
FROM send_sms ss
LEFT JOIN operator_accounts oa ON ss.account_id = oa.id
LEFT JOIN operators op ON op.id = oa.operator_id
WHERE regexp_replace(ss.phone_number, '[^0-9]', '', 'g') LIKE '%{{phone10}}'
ORDER BY COALESCE(ss.sending_date, ss.received_date) DESC
LIMIT 5
```

5. Только чтение: SELECT / WITH / EXPLAIN; без INSERT, UPDATE, DELETE, DDL.

6. Если записей SMS нет — в финальном ответе явно скажи об этом (после статуса auth, если применимо).

7. Если записи SMS есть — краткий вывод по причине недоставки и перечисление найденных записей.
