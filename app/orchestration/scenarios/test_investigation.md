# Сценарий: проверка статуса пользователя

**Идентификатор для JSON поля `scenario`:** `test_investigation`

**Слоты (`slots`):** по ситуации — `user_id` и/или `phone` (строка), в зависимости от того, что удалось извлечь из запроса.

Когда пользователь просит расследовать проблему по пользователю:

1. Если нужны факты из БД — `next`: `db`, `scenario`: `test_investigation`, заполни `slots` известными идентификаторами, в `task` опиши, какие поля вернуть из БД.
2. Ожидаемые факты (пример): `id`, `email`, `is_active`, `is_blocked`, `created_at`.
3. Если ответа БД достаточно — следующий шаг супервизора: `finish`.

Если данных не хватает — `finish` и явно перечисли, что уточнить.

**Исполнитель БД:** сам выбирает алиас (`main`, `billing`, `auth`, если настроены) и один SELECT за шаг; ориентируйся на `task` и слоты.
